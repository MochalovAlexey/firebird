# serial4 and local identity

PG dialect column declarations `serial` and `serial4` use native `INTEGER
GENERATED BY DEFAULT AS IDENTITY`. Ordinary native dialects still resolve those
names as domains; `serial4` is not a cast/data-value type. Persistent tables use
the existing Firebird identity implementation.

Created local temporary tables now support native identity columns. Their values
belong to the attachment-local field, with existing metadata undo copies sharing
one counter. Inserts use the existing default assignment and NOT NULL machinery.
Omitted values and `DEFAULT` generate numbers; explicit values are preserved and
explicit NULL fails. Row/savepoint/transaction rollback does not rewind numbers.
Dropping and recreating the table creates a new counter. No persistent sequence
objects, additional wire state, new public API or new BLR opcode are involved.

This is the captured 1C `serial4` profile, not PostgreSQL sequence compatibility:

- Native identity sequence names differ; PostgreSQL `nextval`, `currval`,
  `setval`, `pg_get_serial_sequence` and ownership catalog APIs are not added.
- Local identities accept native START WITH/INCREMENT BY on CREATE, including
  native ALWAYS/BY DEFAULT behavior. ALTER ADD/RESTART/SET GENERATED support is
  deferred; unsupported forms fail rather than silently ignoring options.
- Native identity NOT NULL/type restrictions remain. PostgreSQL's ability to
  alter a serial default/nullable constraint separately is not implemented.
- Counters use int64 with explicit local overflow checks; integer assignment
  still enforces the column's range. PostgreSQL int32 sequence bounds/CYCLE are
  not implemented, including the three CYCLE sequences in the source database.

`pgwire_serial_checks.py` runs native LTT and real libpq checks in a private
runtime, including the unchanged external selected query 13, default/explicit
values, rollback, independent attachments, metadata undo and Extended Query.
