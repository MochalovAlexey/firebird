## Явное исключение и ограничения

Добавить приём следующих исходных команд:

```sql
SET enable_mergejoin = off;
SET cpu_operator_cost = 0.001;
SET lock_timeout = 20000;
```

Это разрешённое пользователем **узкое исключение** из прежнего запрета пустых
успешных SET. Исключение касается только этих трёх имён. Оно не означает
разрешения игнорировать произвольные настройки или ошибки других SQL-команд.

Контракт: в PG dialect 4 parser принимает SET с `=`/`TO` и одним скалярным
значением — строкой, идентификатором/on/off либо штатным числовым литералом,
в том числе со знаком. Значение игнорируется, не сохраняется и не применяется.
Проверяется синтаксис; PG-типы, диапазоны и единицы измерения настройки пока
не проверяются. Полная грамматика PostgreSQL SET не заявляется.

Исполнение возвращает tag SET в I/T. В E действует прежний отказ 25P02.
Не меняются выбор join, оценки стоимости, lock/statement/connection timeouts,
TPB, конфигурация, данные и настройки attachment. Lock timeout в 20 секунд
**не устанавливается**: продолжают действовать обычные правила Firebird.
Нет новых ParameterStatus, SHOW, состояния для rollback/reset или предупреждений.
Native dialects 1/2/3 сохраняются; прежний PSQL guard сохраняется.

Это отличается от уже реализованных fixed SET: off/error диагностика подтверждает
действующее поведение, а здесь запрошенная семантика намеренно отсутствует.
`standard_conforming_strings`, client_encoding, lc_messages и прежние команды
по-прежнему выполняются/проверяются по своим действующим контрактам.

## Минимальная архитектура

1. Добавить три non-reserved имени в ParserTokens/parse.y и прежний PG-only
   keyword gate Parser.cpp, по образцу уже реализованных настроек.
2. В `set_pg_session` добавить отдельную группу только этих имён. Для RHS
   использовать существующий `pg_setting_value` и `u_numeric_constant`, при
   необходимости с отдельными альтернативами знака. Значения 0.001/20000
   разбирает штатный parser. Не делать atoi/format, вычисление выражений или
   ручной разбор чисел в плагине. **Не расширять pg_setting_value прежних SET**:
   их синтаксис и диагностики должны остаться прежними.
3. Переиспользовать SetPgSessionNode: достаточно одного внутреннего Type для
   трёх игнорируемых настроек и пустого value в существующем конструкторе.
   Execute этого Type явно ничего не делает; оставить короткий комментарий
   о временной совместимости. Не добавлять новые поля для имени/значения,
   attachment state, историю, cache invalidation, API/ABI или registry GUC.
4. Добавить три имени в `SqlInfo::sessionCommand()` для Session/SET. Передавать
   исходный SQL в engine prepare без rewriting; значения плагин не разбирает.
5. Обновить документацию и проверки; закончить этап и отдать diff на review.
   BEGIN, optimizer и lock manager сейчас не реализовывать и не менять.

- Каждая исходная команда отдельно и полный неизменённый пакет

- Проверить `=`/TO, регистр/comments, строковые/числовые значения, альтернативные
  значения: они игнорируются, а не считаются реализованной сменой режима.
  Пустой RHS, выражение вместо scalar и неизвестное имя настройки — ошибки.
- Extended named Parse/Bind/Execute и повторное исполнение возвращают SET;
  нет новых ParameterStatus или изменения standard_conforming_strings.

  остаются допустимыми identifiers. Сохраняются ошибки/проверки прежних SET,

  Parser baseline: 154 shift/reduce, 11 reduce/reduce; новых конфликтов не добавлять.

  эти эффекты намеренно не реализованы. Не запускать известные crash repro.
