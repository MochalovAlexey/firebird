# Задание на реализацию wire-плагинов Firebird

Этот файл — сохранённое описание задачи. Его чтение само по себе не является отдельным поручением; прямые инструкции пользователя имеют приоритет над приложенными планами и review.

Работать в `pg_wire_protocol` на базе `master` Firebird 6, указанной в BASELINE.md. Сохранить существующие изменения. Прочитать применимые AGENTS.md, затем README → BASELINE → ARCHITECTURE → CODEX_CONTEXT → COMPATIBILITY → PLAN → TEST_PLAN. RESEARCH/SOURCES содержат обоснование решений и исходники.

Реализовать общий host дополнительных wire-протоколов в штатном процессе `firebird` и первый загружаемый плагин `PgWire`. Родной протокол сохраняет текущий путь запуска и доступен независимо от дополнительных модулей. Использовать существующие PluginManager/CLOOP, а не отдельный loader. Добавить позиционные списки `WireProtocolPlugins` / `WireProtocolPorts`; точный синтаксис, defaults и ошибки заданы в ARCHITECTURE. Endpoint-specific Bind/TLS settings задавать через существующий `Config` отдельного alias в `plugins.conf`, сохранив два списка. Проверять изоляцию aliases одним тестовым модулем с двумя экземплярами.

Общий host владеет TCP listeners, transport, ограниченными workers, authentication, attachment и shutdown. PG plugin — отдельная `.so`/`.dll`, содержащая framing, protocol state и codecs. Host objects и plugin library включаются в сборку отдельно; `dirObjects` не рекурсивен. Native PACKET/XDR и socket dispatch не используются для PG stream. SQL исполняется локальным engine provider без вторичного сетевого attach.

SQL передаётся в engine prepare целиком, с исходной byte length и без изменения текста. Ограниченный lexer внутри PgWire определяет вид команды, command tag, профиль transaction/session controls и признак tokenless EMPTY. Он учитывает comments, строки и quoted identifiers, но не проверяет grammar, имена объектов, privileges или типы. Общий wire host SQL не анализирует.

После успешного engine prepare плагин сочетает lexical descriptor с существующими `getType()`, `getFlags()`, input/output metadata и affected records. `FLAG_HAS_CURSOR` выбирает cursor/fetch; output metadata определяет singleton output и codecs. RETURNING не превращает DML в SELECT. В I/T неподдержанный control либо UNKNOWN, включая USING wrapper, получает 0A000 до execution; в E успешно подготовленные команды, кроме разрешённого recovery, получают 25P02. Ошибка самого prepare имеет отдельный приоритет по CODEX_CONTEXT. Новые публичные DSQL getInfo items, AST annotations и parser diagnostics для PgWire не добавляются.

Запрещены SQL rewriting, удаление comments из передаваемого текста, разбиение batches, замена `$n` на `?`, подстановка параметров SQL-литералами и эмуляция успешного SET/BEGIN. Совместимость синтаксиса и реальное исполнение определяет только Firebird. Неподдержанный batch передаётся parser целиком и отвергается без частичных эффектов.

В E использовать обычный prepare и plugin-local control descriptor вместе со штатными interfaces. Успешно подготовленные команды, кроме recovery, получают 25P02 без execution. Failed-prepare whitelist ограничен actual `isc_dsql_relation_err` с итоговой nonfatal диагностикой 42P01; одного explicit SQLSTATE недостаточно. Syntax сохраняет 42601, permission — 42501; fatal/shutdown/cancel/timeout/invalid handle/resource/I/O и unknown errors не маскируются. EMPTY определяется lexer только для tokenless whitespace/closed comments; неизменённый текст проходит prepare, и только сочетание признака EMPTY с engine syntax error даёт EmptyQueryResponse после request cleanup, сохраняя прежнее I/T/E. Незаконченный SQL и отдельный `;` остаются errors; native diagnostics/AUTOTERM не меняются.

Предыдущая P5-ревизия прошла целевую Linux/Super loopback приёмку: I/T/E, native transaction/session controls и recovery. В P6 сборка, unit tests и host/startup/Simple Query/transaction/lifecycle/native регрессии прошли. **Известное ограничение native baseline: READ COMMITTED READ CONSISTENCY + AUTO COMMIT не входит в подтверждённую совместимость; SNAPSHOT AUTO COMMIT проверен.** Целевой P6/M1 Linux/Super принят с известными native ограничениями. Shutdown во время ON CONNECT остаётся отдельным исключением: native Debug assertion воспроизводится также без wire endpoints. P7 Extended Query прошёл целевую Linux/Super приёмку: 16 групп. Следующий этап — P8, расширенные codecs; полный M2 требует P9. Результаты и границы покрытия — в [VALIDATION.md](VALIDATION.md). TLS, Windows и другие server modes требуют отдельной реализации и приёмки. Один QueryExecutor на session владеет current transaction: prepare использует текущий handle, включая открытый implicit cycle, либо NULL/system prepare при его отсутствии. Implicit TPB — READ WRITE / READ COMMITTED READ CONSISTENCY / WAIT без заданного плагином lock timeout; в Simple Query implicit commit предшествует CommandComplete, в Extended Query implicit cycle завершается на Sync.

Native SET TRANSACTION начинает transaction/tag BEGIN. Полные controls без native transaction — no-op; retaining/savepoints — 25000/I; повторный start в T — 25001/E. В E полный COMMIT делает native rollback/tag ROLLBACK, успешные ROLLBACK TO и ROLLBACK RETAIN восстанавливают T. Session SET проходят явный native whitelist, RESET имеет реальный effect и учитывает новую underlying transaction при прежнем interface pointer. P7 хранит named/unnamed statements и portals, но не имена savepoints. Named statements переживают commit; Sync в T сохраняет portals. Ошибка удаляет portals и включает discard-until-Sync; Simple Query удаляет unnamed objects, RESET — все objects. SET TRANSACTION при уже открытом implicit cycle получает 25001. AUTO COMMIT/NO AUTO UNDO передаются движку без сканирования опций. BEGIN, START TRANSACTION и RETAINING native grammar не поддерживает; применять `COMMIT/ROLLBACK [WORK] RETAIN [SNAPSHOT]`.

Transport/frame/startup/auth/output timers удалены. Read/write не имеют timeout аргумента и ждут progress, EOF или shutdown; очередь ограничена числом без истечения по времени. Statement-level timeout остаётся 0, plugin lock timeout не задаётся: действуют native StatementTimeout (секунды) и ConnectionIdleTimeout (минуты), 0 означает отсутствие engine cap. Idle shutdown откатывает transaction; следующий Query получает 57P05/close, без reconnect или периодических engine calls. AUTO COMMIT проверять с SNAPSHOT, NO AUTO UNDO — отдельно. Сочетание AUTO COMMIT с READ COMMITTED READ CONSISTENCY воспроизводит native Debug assertion `Savepoint.cpp:833` даже embedded isql без PgWire/server/triggers и исключено из подтверждённой совместимости. В P5 core не изменялся и SQL options не сканировались; исправление native дефекта — отдельная работа. Целевой M1 принят в P6 с native исключениями; evidence — в VALIDATION.

Выполнять P0–P12 последовательно, фиксируя фактические результаты в VALIDATION.md. Сначала штатная сборка/native baseline, решения о ABI/lifecycle/SQL boundary и TLS-зависимости. Профиль приложения исследовать рано; его выбор и трасса обязательны для M3, а не для серверного M1. Служебный SQL и обращения к каталогам не маскировать фиктивным успехом.

Первый работающий сценарий — C libpq PQexec и psycopg2 с `autocommit=True`, без connection context. Обычный `BEGIN` и `$n` пока получают parser error. P7 Extended Query проверен прямым C libpq с нулём параметров и native `?`, включая prepared reuse, async API и text/binary basic types; не объявлять обычную параметризацию Psycopg 3 работающей до расширения parser. Совместимый DDL/DML, включая RETURNING, не ограничивать произвольным SQL allowlist.

Следовать CODEX_CONTEXT для I/T/E, native controls/savepoints, TPB, ownership интерфейсов, полного ISC status vector и codec metadata. В explicit failed block сохранять transaction для корректного ROLLBACK TO; не переносить старую стратегию немедленного полного rollback. Одна активная application transaction на connection — правило PgWire, которое не ограничивает общий host ABI или native Firebird. Auth service общий для wire plugins; прямой вызов EDS ValidatePassword до attach невозможен. Providers ограничить локальным движком, сохраняя остальные database policies.

Python suite мигрирован: 58 live cases и семь групп server harness прошли. Целевой P6/M1 принят; ON CONNECT shutdown исключён из этой приёмки и сохранён как native FAIL, в P6 core не изменялся. В P7 отдельно исправлен release_attachment при нескольких prepared requests одного Statement: все requests этого attachment помечаются unused перед CMP_release. Новый native TCP regression проходит с отключённым PgWire; ON CONNECT !child не исправлялся и не перепроверялся. TEST_PLAN задаёт Linux/Super scope: pytest, resources после прогрева, MON cancellation/attachment termination, database shutdown и shutdown при lock wait/password/partial startup. SuperClassic проверяется только на отказ PgWire при сохранённом native. Новых тестов пауз и срабатывания таймаутов не добавлять; auth-plugin и close/free fault injection не объявлять пройденными. Синтетический driver_probe.json не доказывает выполнения запросов Firebird. Отдельно проверять native coexistence, plugin lifetime, malformed clients, отмену, внешнее завершение sessions и shutdown.

Для каждого законченного этапа сообщать, что реализовано, какими проверками подтверждено и что пока ограничивает следующий этап. Не объявлять M3 завершённым при незакрытых SQL-зависимостях выбранного приложения. Не коммитить автоматически без поручения пользователя.
